# 第三、第四条链路实施计划

日期：2026-10-27。基于main 938a8d2、pg0006、analysis-v2；对应主观互评线与聚合/异常线，不恢复作业总分。

## 交付范围

1. 增量领域表保存互评轮次、任务、原始评价、分析版本、教师处置和幂等命令；复用既有分析快照/任务/输出及worker。
2. 截止且关闭的主观题固定最后有效答案、量表、名单与评审人群；确定性完整匹配，教师确认前重校验输入摘要。
3. 学生匿名本人任务、首次打开的服务端计时、量表分项和非空评语、精确分数校验及提交幂等；越权、超时、关闭与并发提交不得绕过。
4. 原始评价不可改写；固定初步聚合基准，四种检测显式区分不足与正常；教师确认处置/理由后生成新版本重算。
5. 补评仍走预览/确认/本人评分，排除作者和既有评审者；有效逐题候选提供给第五线，不替其他链路计分或发布总分。
6. 教师与学生前端、运行/API/算法说明、增量迁移与纯算法、数据库、并发、真实HTTP及浏览器验证。

## 约束

- 原有DEMO与REAL_INPUT分离，真实互评不使用合成事件或mock回退。
- 业务写入调用领域服务；算法只处理匿名键和固定数据，不导入数据库或Web。
- 主观题归一化结果为候选，不自动宣告正式成绩。零分、缺交、缺评和未知必须分开。
- 新增迁移接在pg0006后，不改写既有迁移；先在algorithm_review_test验证，开发库升级前备份。
- 首版有界支持每题最多300位评审候选、每轮最多2000个任务和有限补评轮次，超界明确拒绝，不悄悄缩减样本。

## 实施顺序

领域模型/迁移 → 纯算法与独立约束 → 快照/分配/评分 → 聚合检测/处置/补评/交接 → 前端 → 集成与并发测试 → 文档/真实HTTP/浏览器 → 独立分支和草稿PR。
