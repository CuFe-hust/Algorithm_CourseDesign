# 教师端与共享数据库的边界

## 1. 复用现有结构

本轮没有模型变更和迁移，Alembic head 保持 `pg0001`。教师、学生、互评共用同一套表；每位开发者本机使用自己的数据库和 `.env`，不共享真实密码或数据目录。

| 共享表 | 教师端用途 | 保护规则 |
|---|---|---|
| `users` | 查询学生；创建 PENDING；经确认更新姓名 | 学号和登录名唯一；不改已有密码、状态与登录名 |
| `classes` | 匹配或新增班级 | 编号唯一；不原地改已有班名；同名歧义需编号 |
| `student_profiles` | 学生当前班级 | 全局身份资料；跨课程冲突禁止自动覆盖 |
| `course_members` | 给当前课程加入学生或恢复学生成员 | 不改变教师角色；不移除文件外的成员 |
| `courses` / `auth_sessions` | 课程授权与原有登录会话 | 不另建教师用户表或登录表 |
| `problems` | 题目身份、编号、题型与归档 | 同课程编号唯一；归档非删除 |
| `problem_versions` | 题干、难度、作答要求、来源和冻结状态 | DRAFT 可编辑，FROZEN 只能复制 |
| `knowledge_points` / `problem_version_tags` | 课程知识点及版本关联 | 不引用其他课程；勾选知识点等分权重，总和精确为 1 |
| `reference_solutions` | 文字答案和标准代码 | 草稿内可替换；仅教师可读 |
| `test_suites` / `test_cases` | 编程配置修订与测试点 | 既有配置只追加修订，不原地修改 |
| `rubrics` / `rubric_items` | 主观题量表修订 | 既有量表只追加修订，不原地修改 |
| `assignment_items` | 检查版本是否已被引用 | 本轮只读，保留旧作业题目/配置依据 |

提交、分析任务、结果等其余业务表保持原模块职责。本轮不写互评或正式成绩。

## 2. 草稿如何兼容只有 FROZEN 的配置表

现有数据库约束只允许 `test_suites.status` 和 `rubrics.status` 为 `FROZEN`，且必须有 `frozen_at`。本轮不绕过该约束，也不把这些配置记录作为可变对象。

每次保存草稿，把当次配置写成一个新的不可变快照，配置 `version_no` 在题目版本内递增。读取教师草稿时取最新配置。允许草稿的快照尚缺测试点或评分维度；这些快照不是可发布题目的证明。只有 **题目版本本身完成完整性校验并冻结** 后，才可供后续作业发布服务使用。

例如：

```text
Problem P1
  ProblemVersion v1, DRAFT
    Rubric revision 1, FROZEN  ← 保存时的不可变快照
    Rubric revision 2, FROZEN  ← 最新草稿配置，读取此项
  冻结 v1 后：题干、标签、答案和配置均不再改动
  复制成 ProblemVersion v2, DRAFT，建立独立配置和答案记录
```

清空已有草稿配置时提交空的 `cases` 或 `items`，不能把已有配置设为 `null`。归档和恢复不会改变任何版本或配置。快照数量随保存次数增长，当前不自动清理，以保留引用安全性。

## 3. 名册匹配规则

- `student_no` 按文本精确匹配，保留前导零；新登录名由学号 `casefold()` 得到。大小写不同的两个新学号若产生同一登录名，整批拒绝。
- 明确 `class_code` 时按编号匹配，并核对班名；只填班名时，唯一同名班直接复用，多班同名必须补编号。
- 新班级未填编号时使用班名 SHA-256 派生的 `TCSV_...` 稳定编号，并再次核对现有记录。
- 已有学生资料一致时可复用身份并加入当前课程；姓名或班级有变化时，只允许当前课程原有学生且没有其他有效课程成员关系的身份更新，并需显式确认。
- 若资料变化涉及其他有效课程，返回逐行错误，请数据库负责人核对。当前表把班级建模为全局学生属性，教师端不把它误当成课程私有属性。
- CSV 只改变课程成员，不自动补进既有 `assignment_participants`。历史作业的名单与班级快照保持原样。

## 4. 并发与兼容约定

题目服务按题目→版本加行锁，使用时间戳乐观检查；导入按全局事务锁→班级→用户→资料→成员锁定相关记录。唯一约束作为最后防线，冲突统一 409 并回滚。

其他组员发布作业时，需固定具体 `problem_version_id`、`test_suite_id` 或 `rubric_id`，检查归属、题型、完整性及版本状态，禁止引用可编辑草稿。后续若需要真正可变的配置草稿、激活令牌或操作审计表，应由数据库负责人协调新增迁移，不能修改已应用的 `pg0001`。
