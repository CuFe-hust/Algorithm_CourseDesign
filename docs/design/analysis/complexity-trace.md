# 已通过代码的复杂度分析：执行轨迹计数与递推推断（已实现）

## 1. 它回答什么

一段**真实通过**的代码，在这类输入上，工作量随输入规模怎么长、空间怎么长。给学生的是一条递推式（递归程序）、一个闭式类别、逐档的精确计数、置信度和适用范围。它不参与评分。

资格条件与上一版相同：`ACCEPTED`、`is_mock=false`、通过点数等于总数、当前执行环境内、语言受支持。此外新增一条：该语言必须有执行轨迹采集器。

## 2. 为什么换掉计时

上一版的根本问题是拿墙钟毫秒当被测量。时间有噪声，而且输入解析的线性开销是所有解法的下界，于是出现两条无法靠调参解决的结构性缺陷：

- `n` 与 `n log n` 在整个可测区间内只差不到 1.2 倍，R² 只差约 0.0006，40 次带噪声的对照有 13 次分错；为了补救又长出"log 因子由结构裁定"的规则。
- 程序跑不赢读输入就被判为"只能给上界"，退回静态结构分析；6 组对照里只有 2 组由实测定案。

换成本方案后，被测量是**整数的执行事件计数**：同样的两个程序在 `n=512` 上计数相差约 6 倍，分类不再依赖曲线拟合的边际差异；输入解析的开销用同一输入上的最小读取程序的计数精确减掉，不需要"跑赢读输入 1.5 倍"这类阈值规则。计数与机器、负载无关，同一份确定性程序两次运行的结果逐个事件相同。

## 3. 三层结构

**输入层。** `probe.py` 保留上一版的 11 个输入形态族，并新增 10 个族覆盖题库里其余的输入格式（三个整数、数组加查询、两个数组、首行 `n m` 加 m 行、树加根加查询、两个大整数字符串、字符串列表、网格加单词、三角形行、背包）。档位规则改为两种：`max_n` 较大的题按倍增梯子（32、64…最多 16384，适配器按计数预算自行截断）；`max_n` 很小的题（汉诺塔 22、全排列 8、N 皇后 10）在 4 到上限之间均匀取 6～8 档。生成仍是确定性的：同族、同规模、同种子生成逐字节相同的输入。

**采集层。** 每个语言一个适配器，把一次执行变成 `LadderTrace`：每档记录 n、工作量总数、行/跳转分解、库函数折算量、各函数的调用次数与逐调用样本（参数规模、帧内工作量、递归子调用参数）、最大递归深度、峰值分配字节。统一结构见 `trace/schema.py`。

每份报告有预算：Python 累计约 200 万事件（超过就停止加档），内存峰值只在 n≤2048 的档位采集（`tracemalloc` 在大规模上比计数本身还慢，而空间类别在更小的档位就能看清）；C/C++ 累计约 800 万插桩行、单档 10 秒。实验里单份报告的采集与推断中位数约 3–5 秒，最慢约十几秒，均低于 60 秒预算。

**推断层。** `trace/fit.py` 做闭式类别拟合；`trace/recurrence.py` 从调用树里读递推式并求解；`trace/infer.py` 合并两者、生成逐行证据和限制说明。

## 4. 工作量单位

| 语言 | 单位 | 说明 |
|---|---|---|
| Python | 执行的行事件 + 跳转事件 + 已知库函数折算 | 行事件单独不够：`for x in a: s += x` 写在一行时每次循环不产生新的行事件，512 次循环只记到 14 个事件；跳转事件按回边计数后恢复为 526。`sorted`/`heapq`/`bisect` 等 C 实现的库函数在调用事件里拿到第一个实参的规模，按理论代价折成单位；表外的库函数按常数计并写进限制说明 |
| C/C++ | 被插桩源码行的执行次数（gcov）+ 标准库算法的折算量 | 测量构建用 `-O0 -fprofile-arcs -ftest-coverage`。Apple libc++ 把基础类型的 `std::sort` 等实现预编译在库里（`extern template`），编译器插桩看不到其内部，所以适配器按调用点的执行次数与档位规模把它们折算成理论代价；这部分折算单独拟合出增长类别，与可观测工作的类别取较高的一档，置信度封顶 MEDIUM |

所有语言都额外减去**输入解析基准**：平台用同一档输入运行一个最小读取程序（Python：`read().split()`；C/C++：逐 token 读入），把它的计数从学生程序的计数里减掉。减完的余量才是算法自身的工作量；余量在全部档位上是常数时，算法为 `O(1)`。

## 5. 推断

**闭式拟合。** 对每档的精确工作量在 {1, log n, n, n log n, n², n² log n, n³, 2ⁿ, n!} 上拟合。`O(n)` 以上每个类别除了主项还带一个自然低阶项（例如 `n log n` 配 `+b·n`，`n²` 配 `+b·n`），因为计数里始终混着读入残留与逐元素循环的线性项；只用 `a·f(n)+c` 时低阶项会把相邻类别判错（第一轮实验里 5 个 `n log n` 程序因此被判成 `O(n)`）。类别用 AIC 比较——残差加上参数个数惩罚——避免低阶项"买"到更高的类别；主项在最大档位占比低于 20% 的退化拟合直接丢弃。置信度由 AIC 差与档位数决定：至少 5 档且 AIC 差 10 以上给 HIGH，至少 4 档且差 4 以上给 MEDIUM，其余 LOW。绝对 R² 只用来拒绝"什么都解释不了"的序列。

**递推提取（递归程序）。** 从调用树里识别自递归函数，量三个东西：

- 每帧的递归子调用个数 `a`；
- 子调用参数相对父调用的缩放：比例恒定为折半、差值恒定为递减、参数为常数为常数参数，比例随数据变化则标为 `DATA_DEPENDENT`；
- 每帧的非递归工作量（含辅助函数，如归并的 merge）随参数规模的类别。

然后用 Master 定理（折半）、求和规则（单路递减）、指数规则（多路递减）解出闭式。解出的闭式要回去和实测总量校验：类别一致才作为解释发布，不一致时以总工作量拟合为准并把分歧写清楚。数据依赖的递归（快排、随机选择）不硬套递推，报告写明"在该输入族上的平均增长"。

**标准库算法的折算（C/C++）。** Apple libc++ 为基础类型提供了 `std::sort`/`stable_sort`/`partial_sort`/`nth_element`/`make_heap`/`sort_heap` 的预编译显式实例化，学生代码调用的是库里的实现，gcov 和覆盖率插桩都看不到。适配器从覆盖率的行计数里取这些调用点的执行次数：每次调用按档位规模折算 `n log n`（排序类）或 `n`（选择/建堆），若某个调用点在每档被调用很多次且调用次数随 n 增长（循环里反复排小容器），则只按每次常数计，避免把 O(n) 抬成 O(n² log n)。折算量单独拟合类别，与可观测工作取较高者；报告的限制说明会写明这部分是按输入规模估算的。

**逐行证据。** 对每个执行过的源码行，拟合它的执行次数随 n 的类别；主导行（类别等于总类别的行）进入报告，学生看到的是"第 13 行执行次数 Θ(n log n)"这种可核对的事实。

**空间。** Python 用 `tracemalloc` 峰值（单独一次不带监控的执行，避免采集器自身分配污染）；C++ 用全局 `operator new/delete` 记账的峰值；C 不采集。峰值随 n 的增长做同样的类别拟合；递归深度另做一次拟合，空间类别取两者较高的一档。

## 9. 仍然给不出结论的形态

报告里会逐条写明，不会用类别糊过去：

- 没有可伸缩输入合成器的题（固定输入，例如数独）：`NOT_MEASURABLE` 并给原因。
- 输入值决定复杂度的算法（哈希、快排最坏、负环、依赖数值分布的算法）：只报告在该输入族上的增长，不声称最坏情况。
- 库函数不可见：Python 表外 C 内建按常数计；C 的 `qsort`/`memcpy` 等 libc 函数不可见；C++ 大部分标准库模板可见，但显式链接的库函数不可见。
- Java：本机没有可用的精确循环计数采集器（JVMTI 只给方法进出，JDI 单步太慢），请求直接返回 409 并说明，不退回词法猜测。
- 空间：C 不采集分配；C++ 不含调用栈与直接 `malloc`；Python 的峰值含解释器自身分配，已扣最小档基线。
- 比 `O(log n)` 更慢的增长（log log n、反阿克曼）不在类别目录里，会落在 `O(log n)` 或 `UNKNOWN` 并注明。
- 计数预算内看不到的规模效应（常数极大、缓存效应、只在很大 n 才出现的行为）：结论只对已测档位范围成立。
- 非确定性、多线程、外部依赖、交互式输入、超时：低置信或 `FAILED`。
- 输出巨大的程序：输出被丢弃，格式化工作计入；指数级题只能测到很小的 n。
- 递推式未被还原时（数据依赖递归、C/C++ 缺少逐调用参数）：只发布闭式类别与逐行证据，报告写明没有递推式。
- C/C++ 的标准库算法内部不可见：排序/堆类调用按输入规模折算，属于理论代价估算；若学生把算法封装在自定义库里编译成外部代码，轨迹同样看不到。
- C/C++ 的输入读取基准用数字读法：若题目的输入不是数字（如字符串题），基准读取立即失败，等于不扣读入开销，类别退回含读入的总工作量。

## 11. 自动发现输入方案（2026-11-09）

第一版采用本地规则，不调用运行时大模型。输入说明和约束提供语义依据，已有测试用例提供布局及已知答案。识别支持单整数、整数数组、数组附排名/固定参数、两字段记录、方形伸缩矩阵、常见边列表，以及字符集明确的一或两行字符串。变量数值范围支持整数、科学计数法、幂和常见绝对值写法。多组、EOF、交互式输入及尚不能确认的复杂语义返回具体原因。

自动识别只负责输入结构，复杂度仍来自学生代码的执行轨迹。系统不把参考解的增长类别套用到学生代码上。

验收顺序：

1. 推导规模、字段、值域、排序/互异/连通等已支持约束，检查与已有测试用例是否一致。
2. 编译数据库中的教师参考代码，核对已有测试用例的答案；也支持说明中的单个匹配语言代码块。
3. 从小规模开始生成并独立检查输入，运行参考解。大规模超时会收缩档位；至少保留三个不同规模。常数工作量属于合法结果，不再要求工作量增长 1.5 倍。
4. 缓存每个已验收输入的参考输出摘要。学生代码在这些输入上先做输出校验；不一致时不给出复杂度类别，说明需要核对生成规则和代码，原判题结果保持不变。输出比较沿用现有文本检查器，多解、非确定性输出可能无法通过此项检查。
5. 再采集轨迹；无排序约束的数组分别测随机、升序、逆序，一行字符串补测重复字符，两行字符串补测相同字符串。主图保留默认分布，其余分布的类别和测量范围存入 `trace.scenarios`，同时显示在报告限制说明中。

配置复用现有 `problem_complexity_profiles`。自动方案使用系统来源 `SEEDED`，`spec.adaptive` 保存生成器版本、输入/参考代码/测试用例指纹和验收状态；`spec.validation` 保存种子、已知用例验证记录和生成输出摘要。自动方案失效后重新验收，教师来源 `TEACHER` 不会被自动覆盖。参考执行在数据库事务外完成，发布缓存时短暂锁定题目版本，避免重复记录。

已确认不支持的格式会缓存原因，题目资料变化后再尝试；运行验收失败使用 `VALIDATION_FAILED` 状态，允许在资料不变时显式重试，以免临时预算或工具链问题被永久缓存。

报告保存配置版本和种子；旧实现报告及配置版本变化后的报告可以重新生成。不可测报告支持显式重试，保留原有幂等、重试次数和 worker 租约约束。教师批量入口允许未配置的题目进入自动发现流程。

规模具有明确条件：矩阵以边长为 n，图以顶点数为 n 并生成稀疏简单图，数组的独立参数可能固定为样例中的合法值。它们都只代表这些输入路径，不代表多参数复杂度的完整表达式，也不证明最坏情况。规则识别和参考解执行不能证明任意自然语言约束已被完整理解；无法确认的输入应继续补充支持，不能通过放宽约束提高表面覆盖率。

```bash
cd backend
```

### 11.1 生成器 v2 扩展

在已有形态族中加入可组合布局：有界整数字段、数组、重复记录、文本和构造图边。无需为新题建立题号映射，也不新增数据库枚举。布局同时描述输入行数、字段数和参数间关系；独立校验器检查生成输入及已有用例。

新增或完善的格式包括：

- 两/三个整数、双数组、数组加单值查询、两参数头部加记录；记录数量以输入说明中的参数为准，避免样例中 `n=m` 时误选计数参数。
- 三角形、单参数方阵、双参数矩阵、字符网格和网格加单词；检查矩阵元素总数上限、网格端点和单词长度约束。
- 树加根加查询、关系边加查询、字符串区间查询；端点按当前节点数或字符串长度检查，树严格保持连通且边数为 `n-1`。
- 十进制大整数、字符串列表及字符串查询；检查前导零、单串长度、字符集和已识别的总长度上限。

约束解析区分容量 `W` 与重量 `w_i`，保留 `a_i<=n` 这类对当前参数的依赖。双数组分别保留值域与元素和上限。常见整数幂、科学计数法和绝对值由受限整数表达式解析器处理，不执行任意 Python 表达式。尚不能完整校验的参数算术、质数、精确和、元素出现次数等约束返回不支持。

背包类记录额外测量 `within_capacity` 分布，优先生成能放入背包的物品，避免默认随机重量全部超过固定容量、只测到跳过物品的路径。合法的大重量仍可出现在默认分布，原始用例也不会被收紧。各分布仍分别发布测量结果。

规模说明记录实验条件：两参数可能按固定比例共同增长，容量或第三参数可能固定，字符串列表的单串长度可能固定。报告由这些路径上的动态执行计数推断增长，不能还原任意多参数复杂度，也不能据此证明最坏情况。

v2 的同一组 70 题实验中，**63 题通过真实参考解验收（90.0%）**，比首轮增加 33 题。剩余 7 题为固定数独（P37）、图着色（P38）、后缀表达式（P53）、数组操作流（P54）、队列命令流（P55）、参数依赖不同元素个数（P56）、元素出现次数约束（P63）。这些题的已有人工预设方案继续可用，自动发现保留不支持原因。这个指标衡量自动生成方案的验收覆盖率，**不是复杂度类别准确率，也不代表任意新题的覆盖率**。
