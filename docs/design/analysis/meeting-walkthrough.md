日期2026-10-26；设计讨论材料，不代表分析代码已实现。入口：[设计稿](../../superpowers/specs/2026-10-26-analysis-framework-design.md)、[4K图](../../assets/diagrams/analysis/README.md)。

## 开场

“教师和学生入口已由两位队友推进，分析模块接数据库中的题目、名单、提交和评测结果。我们先确定每条线用什么输入、等什么结果、产生什么输出，再各选1～2个黑盒研究；算法接口稳定后，替换实现不需要重写页面。”

当前main已含学生LOCAL评测与教师题库/名单；教师账号/作业发布最新在teacher-student-integration分支，正式整合前先确认团队使用的head，避免两人同时新增pg0004。

## 对着图03讲六条线

1. 编程线：复用已有真实LOCAL评测。分析读取判定和采用候选；目前通过点数不是完整加权得分证据，计分适配必须有明确规则。
2. 内容证据线：代码相似、文本相似、AI辅助信号都是独立黑盒，可与评测和互评并行。先出证据，教师决定是否处置，不自动扣分。
3. 互评线：答案和人群冻结→匹配→教师开放→学生评分。算法之外有两个真正的人工等待，不能拿随机输入冒充已经评分。
4. 聚合/异常线：评分集固定→初步聚合→偏离/长期偏差/关系检测；时长可早算。教师处置之后补评或重算，形成新版本，不覆盖原始评分。
5. 成绩线：编程与主观候选结果在此汇合。按题分/权重/缺交政策结算，再教师确认发布；mock、待评或缺证据不能当真分。
6. 学习线：知识点掌握、能力、基础统计、经验难度依赖明确成绩版本；行为指标依赖事件，可独立运行。展示时标明范围、样本、缺失和版本。

图中的四个“∥”讲的是依赖可以并行，第一版单worker也可以先跑通，不需要开会前解决分布式调度。

## 对着图04认领黑盒

优先认领匹配、聚合、异常检测、相似性、掌握/能力等算法研究。JUDGE已有执行器，基础统计不是必须包装成复杂研究算法。四种异常可以作为同一研究课题的子项。

建议每人只挑1～2个主黑盒。认领时写：负责人、输入样例、输出样例、基础算法、改进算法、指标、复杂度、最小实验规模和交付日期。不要只写“负责分析一条线”。

| 黑盒组 | 可研究的比较 | 接回系统的验收 |
|---|---|---|
| 匹配 | 基线与改进方案的可行率、负载公平、重复关系 | 硬约束全部通过，返回完整映射或明确无解 |
| 聚合 | 均值/稳健基线与改进方案；不同异常比例的稳定性 | 同一评分快照可复现；无评分不补0 |
| 异常检测 | 四类信号、阈值、误报/漏报、样本不足 | 返回可追溯证据，不自动处罚 |
| 相似性 | 模板干扰、变量改名、公共表达、片段定位 | 作品对及可解释片段，比较范围明确 |
| 掌握/能力 | 可解释基线与模型差异、缺数据、不同难度 | 按学生/知识点返回估计、样本和缺失 |

AI辅助信号先固定研究接口，方法未实现时如实标记；不要在会议中把演示随机数说成“AI率检测准确率”。

## 公共框架统一负责

读库和固定快照；权限；依赖调度；人工等待；任务重试；输出检查；版本/seed/输入hash；mock来源传播；数据库结果保存。研究者只实现纯输入→输出函数，不再写第二套数据库或页面。

## 会议需要落定的三件事

- 每人认领哪些主黑盒，哪天交第一份可运行基线与实验。
- 正式编程计分、缺交政策与异常处置是否影响发布；未决定前框架保留不可用/阻塞，不能替真实学生决定。
- 三人共同使用哪个Git基线，教师联调分支如何合入；后续迁移按最新head统一分配。
