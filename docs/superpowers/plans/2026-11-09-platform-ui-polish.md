# 网页整体 UI 优化执行计划

> 执行阶段使用 superpowers:executing-plans，按下列复选框跟踪。

**目标**　让教师和学生在高密度教学页面上读得清、找得到操作、看得懂结果。
**基线**　执行时核对 origin/main，当前为 837fa38。现有技术栈 Vue 3、TypeScript、Vite、pnpm。
**技能**　用 frontend-design 指导版式、中文文案和代码落地。用 superdesign 在执行期为典型页面做现状对照和视觉方案，先核对环境与仓库初始化要求。采用现有本地合成课程作为页面验收样本。

- [x] **盘点页面与记录现状。** 以 frontend/src/app/router.ts 枚举角色和路由，按登录/选课、教师、学生归类。用 11 月 8 日会议实操截图对照最新 main，标记小字、低对比、英文眉题、同名题作业归属、状态文案冲突、互评原始 JSON。保留改前截图与优先级。把复杂度页面新功能纳入巡检。
- [x] **确定视觉规范和代表页。** 以教师逐题结果、学生作答和个人章节表现先做方案。用中文界面字体及可靠系统回退，代码用等宽字体。建议正文 15–16px，表单和表格主要内容至少 14px，必要辅助文字约 13px。合并重复说明和装饰性英文小字，保留评分来源、截止、证据不足及数据边界等关键信息。验收时明确正常、等待、错误、成功和禁用的外观及文案。
- [x] **实施共享基础。** 首先处理 frontend/src/styles.css、workspace.css 和教师/学生 Layout，再迁移表单、表格、按钮、状态、空态和焦点样式。整理页面内硬编码 8–12px 规则，检查公共 Markdown、公式和代码块的阅读样式。保持角色、路由、评测、互评及评分契约。
- [x] **分流改进业务页。** 学生端覆盖作业与作答、提交历史、我的互评、学习报告、个人章节表现。教师端覆盖概览、题库、作业、学生名单、互评复核、逐题结果、分析中心及相似/复杂度页面。详情明确显示所属作业，筛选区写清是提交状态还是评测状态。互评预览把作品数、任务数与负载做成可扫描摘要，原始 JSON 可放详情。为无结果和失败状态写清下一步动作。对“模拟联调”等旧文案，先区分作业种子数据和界面文案来源，按实际评测来源展示。
- [x] **可读性与交互验收。** 检查 1440px、768px、390px 宽度及 200% 缩放，页面级无横向溢出，宽表在独立容器可横向查看。普通正文对比度至少 4.5:1，状态有文本而不只靠颜色。键盘能完成导航、表单和弹窗，焦点可见。覆盖空、加载、失败、成功、禁用，以及长标题、多行答案和大表格。
- [x] **跑回归与交付。** 在 frontend 执行 pnpm test 与 pnpm build。用合成账号走登录选课、编程提交/历史、主观提交、互评填写、教师固定结果并生成分析、学生查看 B0/D1。保存代表页改前改后截图、设计规范、覆盖清单和实测记录。对本轮没有实测的分支单独标注。UI 变更与报告交付分别审阅。
