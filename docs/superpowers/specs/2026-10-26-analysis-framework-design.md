# 分析框架：全链路、算法黑盒与数据依赖

日期：2026-10-26。状态：用户已确认，框架/持久化/接口/合成演示已实现；研究算法与真实互评/成绩领域服务仍按边界后续接入。

## 1. 本轮目标与已有共识

所有讨论过的链路均纳入范围。先搭可替换算法的公共框架、固定输入输出，再由三人各选1～2个算法研究。今晚讲解应能回答：数据从哪里来、哪些可并行、哪些必须等待、算法交付什么、如何接回网站。

本轮框架交付目标是能运行合成场景、持久化任务/快照/输出、展示各条线的依赖和等待状态。真实学生互评、正式成绩发布不是“有接口空壳即完成”；先保留明确接入契约与状态，不伪造已经发生的学生评分或教师决定。后续按同一契约逐段接真实业务。

业务数据先经后端校验入库；分析服务从库读取并形成快照，调用不依赖Web和数据库的纯算法接口，再写回结果。浏览器可触发创建任务及查询结果，不直接决定输入身份、分数有效性或算法输出。

## 3. 选择的架构

团队已选择：先整体数据依赖，再定义黑盒，最后并行研究算法。

比较：仅写算法函数不能验证落库与等待；直接实现所有教师/学生业务会扩大本轮范围。采用“任务与数据流框架＋算法插件＋独立场景演示”，先保证每条线都有入口、输入输出、依赖与明确状态，再逐步接业务和真实算法。

三层：

1. 编排/存储层：权限、快照、任务、依赖、幂等、状态、持久化、审计。
2. 算法插件层：输入DTO→输出DTO；不导入FastAPI、SQLAlchemy，不自行读库，不创建浏览器请求。
3. 查询/接入层：教师看本课程批次和证据；学生只看本人已授权结果/任务，服务端单独投影匿名数据。

执行阶段用单worker顺序消费已就绪任务即可。图中的并行表示数据依赖允许并行，研究可以并行；本轮不引入多进程并行执行保证。

## 5. 数据依赖与并行约定

- 快照后同时展开：现有评测结果读取、代码相似、文本相似、AI信号、主观匹配、行为分析。无相应题型时SKIPPED，而不是失败。
- 互评线：固定答案→匹配→教师开放→等待学生→固定评分→初步聚合。
- 初步聚合后并行：单次偏离、长期偏差、关系检测；时长检测只依赖事件/评分，能更早运行。
- 所有已配置的检测终态汇合后进入教师复核；不足和未实现要可见，不当成“未发现异常”。失败能否豁免必须由教师记录理由。
- 处置/补评→新评分快照→重新聚合；不回写A1版本、不自动无限迭代。长期偏差与能力模型本轮仅输出证据，不自动参与当前轮聚合权重，避免相互递归。
- 代码/文本/AI信号先为独立证据，不自动扣分、不默认阻塞成绩；教师显式处置才影响后续。若未来课程规定为发布门槛，需有版本化政策。
- 发布后L1/L2/L4/L5可并行；L3独立，面板按时间和版本汇合。L1/L2暂不相互依赖，后续选择具体模型后再改依赖版本。
- 人工等待是WAITING_HUMAN，缺输入是WAITING_INPUT，不占worker，不轮询生成虚假输入。

## 6. 算法目录和输入输出边界

算法编号ALG-*与既有B/TD/R任务编号分开。所有数组元素使用字符串ID；分数/比例使用十进制字符串；时间为带时区UTC。算法输入只含必要业务标识，不传真实姓名学号。

| 编号/插件键 | 输入payload（必需内容） | 输出payload（必需内容） | 首版实现状态 |
|---|---|---|---|
| ALG-JUDGE / judge_adapter | 采用提交/结果ID、test_suite、执行上下文、完整性 | 原评测摘要、可用计分依据/不可用原因 | 复用已有，不占研究名额 |
| ALG-ALLOC / allocation | answer_key/author_key、候选reviewer_key、每份人数、禁止关系、已有边、历史、seed | feasible、edges、unmet_constraints、load_metrics | 确定性基础匹配；硬约束必验 |
| ALG-AGG / aggregation | 答案key、量表版本/满分、分项评价、有效性、最终权重、最低样本数 | normalized_score或null、valid_count、dispersion、reason | 简单可解释基线；正式策略后续确认 |
| ALG-DEV / deviation | 原评分、固定聚合基准、阈值、最少样本 | evaluation_key、evidence、sample_count、status | 先预留，演示mock |
| ALG-BIAS / reviewer_bias | 跨作品评分及对应基准、时间范围、最少样本 | reviewer_key、方向/程度、依据、status | 先预留，演示mock |
| ALG-TIME / review_timing | 任务事件、服务端时间、题目特征、阈值 | task_key、时长、证据、缺失/不足 | 先预留，缺事件不得造真数据 |
| ALG-REL / relationship | 分配边、评分、固定基准、历史、最少样本 | 可疑边/群体、证据、样本、status | 先预留，演示mock |
| ALG-CODE / code_similarity | 同题代码集合/语言、题干模板、比较范围 | pairs、similarity、matching_spans、method | 先预留，演示mock |
| ALG-TEXT / text_similarity | 同题答案、题干/模板/参考、比较范围 | pairs、similarity、matching_spans、method | 先预留，演示mock |

## 7. 统一调用格式与样例

公共输入：schema_version、algorithm_key、snapshot_id、input_hash、parameters、seed、payload。输出：schema_version、algorithm_key、implementation_name/version、input_hash、is_mock、status、payload、evidence、limitations。运行ID、起止时间与数据库ID由框架记录，不由算法生成。

status为OK / INSUFFICIENT_DATA / INFEASIBLE / NOT_IMPLEMENTED；异常执行由框架记FAILED。空数组、分数0、缺失null必须区分；mock不可混进正式发布，即使数值看起来合理。

匹配输入示例（合成身份，完整类型后续由Pydantic/JSON Schema固定）：

```json
{"schema_version":"analysis-v1","algorithm_key":"allocation","snapshot_id":"synthetic-round-1","input_hash":"由框架计算的SHA256","parameters":{"required_reviewers":2},"seed":20261026,"payload":{"answers":[{"answer_key":"a1","author_key":"u1"},{"answer_key":"a2","author_key":"u2"},{"answer_key":"a3","author_key":"u3"}],"reviewers":["u1","u2","u3"],"forbidden_edges":[],"existing_edges":[],"history":[]}}
```

输出示意：feasible=true，edges为(a1,u2),(a1,u3),(a2,u1),(a2,u3),(a3,u1),(a3,u2)，每份2人、每人2份；人数不足则输出INFEASIBLE和缺口，不偷偷减少人数。真实名册无需传进算法。

插件验证要求：输入哈希/算法键/版本对应；分数和相似度有范围；引用只能来自本次快照；一份答案不得自评/重复评；负载/人数检查在框架复验，不只相信插件返回的feasible。

演示聚合基线暂定：量表各维分数相加得到单次总分，除以量表满分R得到[0,1]比例；每条评价的最终权重w非负，w=0不参与，样本至少2条；结果为Σ(w×比例)/Σw。无有效评价或未达样本数返回null及原因。维度不再额外赋权，避免重复计算满分权重。OVERRIDE在DEMO中另存有界题目分及理由，保留聚合原值，不伪装成学生评价；本基线未被确认为正式政策，只用于DEMO。

## 8. 框架持久化和生命周期（拟新增）

独立的analysis_batches、analysis_input_snapshots、analysis_runs、analysis_artifacts四类框架记录：课程/作业/范围、截止与政策版本、匿名输入及hash、算法/参数/seed/版本、依赖的具体run/artifact版本、执行状态/租约/错误、输出与模拟来源。名称为设计候选，迁移前最终核对。

批次区分DEMO与REAL_INPUT：DEMO只使用合成学生/评分/人工决定；REAL_INPUT读取真实数据库事实，缺的互评/事件输入就等待，不从DEMO借数据。所有派生结果传播is_mock；混合数据只要任一来源mock就为mock。真实模式缺少插件返回NOT_IMPLEMENTED，不自动回退mock。

任务状态：WAITING_INPUT/WAITING_HUMAN/READY/RUNNING/SUCCEEDED/FAILED/SKIPPED/CANCELLED。算法返回不足/无解/未实现也保存为SUCCEEDED的业务结果，但不满足“需要有效得分/可行映射”的下游条件。下游显式检查业务status，不仅看执行成功。

依赖不满足时子任务停留WAITING_INPUT并保存blocked_by、upstream_status、reason；上游失败/取消/不足/未实现不自动跳过。显式重试生成attempt；输入或算法版本变化生成新任务，旧结果保留。仅DEMO允许显式模拟人工决定，不能靠run自动消除人工等待；发布节点仍禁止真实采用mock。

同一逻辑请求request_id幂等；任务签名至少含批次、步骤、输入hash、算法实现版本、参数hash、seed。失败重试沿用输入和签名，新增attempt，不覆盖旧输出。过期worker提交结果必须被attempt_token/租约拦截。首版单worker不等于可以不处理崩溃。

读库快照在一致性事务中采集，固定入选提交、评价、题目/量表、名单、截止/政策、执行上下文和采样时间。发布前检查相关配置版本/hash，不因后来修改数据库而默默改变算法输入。

通用四类记录不替代正式互评/评价/成绩领域表。S3/S4/R1/G3在演示中由明确标注的合成事件驱动；真实开放/评分/处置/发布接入需要另增领域表与服务，不能把JSON artifact当成已发布真实成绩。

## 9. 接口与文件边界（均为规划）

- GET /api/v1/analysis/catalog：插件、输入输出schema、版本、实现状态。
- POST /api/v1/analysis/courses/{course_id}/batches：本课程教师创建DEMO/REAL_INPUT批次，服务器读取事实；不接受客户端伪造评分作为真实输入。
- GET /api/v1/analysis/batches/{batch_id}：依赖图、各任务状态、等待原因、数据来源、可见结果。
- POST /api/v1/analysis/batches/{batch_id}/run：只把满足依赖的任务置READY，等待人工节点不自动跨越；幂等request_id。
- POST /api/v1/analysis/batches/{batch_id}/demo-events：仅本课程教师、仅DEMO，按expected_version与request_id提交预定义的合成OPEN_REVIEW/SUBMIT_REVIEWS/RESOLVE/RELEASE事件；事件数据由固定合成fixture提供，拒绝任意真实评分字段。此接口不作为正式教师处置API。真实人工接口按next-phase契约后续实现。
- 学生现有接口保持兼容；本轮不向学生开放通用artifact读取。匿名评审/本人已发布成绩使用专用DTO。
- backend/app/analysis现有judge文件保留；新增framework/（契约/目录/依赖/运行服务）、algorithms/（独立插件）、repositories/（读库适配）；新增router单独挂接。实际文件名由实施计划固定。

## 10. 演示与验收

1. 合成6名学生、2类题、每份2位评审者；匹配、人工等待、合成评分、聚合/检测、模拟教师处置、模拟结果/学习分析完整展示，所有模拟来源显眼。
2. 同一快照/参数/seed产生相同结果；读结果不重新随机；算法替换不改变前端读取结构。
3. 覆盖匹配无解、缺评、零分、时长缺失、历史不足、算法未实现、上游失败、越权、重复请求和A→B→A输入版本。
