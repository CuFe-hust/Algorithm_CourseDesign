## 2. 已确定调整的同步

| 编号 | 最新决定 | 本轮同步内容 |
|---|---|---|
| AD01 | 开发阶段先本机编译／解释执行 | 执行接口同时定义 LOCAL 和后续 LINUX_SANDBOX；本机有进程生命周期、墙钟和输出保护，不误称已经完成 Linux 沙箱 |
| AD02 | 本机暂不测 CPU／内存 | LOCAL 为 is_mock=false、measurement_status=UNAVAILABLE_LOCAL，资源可空；空值不使本机结果 FAILED，不以墙钟冒充 CPU |
| AD03 | 学生只需单题／一次提交汇总 | API 示例移除 case_results；汇总保留 verdict、通过数、总数、环境、可用资源及编译诊断。删除本轮必建逐点表的要求，内部仍逐点运行并累计通过数 |
| AD04 | 总执行预算主要由教师负责 | 教师配置／发布校验，评测提供预算公式、节点上界及执行保护；学生仅展示反馈。现有接口无总预算字段记入 C09，不由学生接口私自补教师管理功能 |
| AD05 | 实际账号不跨课程混用教师／学生身份 | 撤回基于该假设的风险和验收场景，保留现有课程角色鉴权，不增加新的账号／角色模型或特殊重置策略 |

LOCAL 与 Linux 的结果都记录 execution_mode 和 runtime_profile；最佳候选和进度按服务器绑定的当前评测上下文选择。LOCAL 两个资源键为空时仍沿用原比较顺序，跳过相同缺失键继续比提交时间；不把开发环境与正式资源数据混排。

## 3. 容量与保留参数的性质

以下数字是设计中的可配置开发默认，并非用户必须逐个决定的产品规则，也不是当前系统已启用的限制：

- 提交每账号 10 次／分钟、突发 3，个人同时未结束任务上限 20；节点积压和磁盘水位在部署配置中明确设置。
- 手动重评冷却 60 秒，单任务累计最多 3 个学生恢复周期，每账号每小时 10 个新周期；自动尝试每周期最多重试 2 次。
- 登录与来源联合限流、body 上限、故障熔断按接口／评测设计执行；部署压测后调整，使用稳定账号标识计数。
- 编译诊断单份 16 KiB、30 天、总体默认 256 MiB；节点结构化日志 7 天／1 GiB；详细故障诊断 90 天；过期会话和短期计数按相应策略清理。

已确认的个人执行上限 3、登录空闲 2 小时和绝对 24 小时不因上述技术默认值调整而改变。429／503 表示未接收，需保留草稿并按 Retry-After 重试；已接收提交不会因后来积压而删除。

## 4. 已明确归教师端的账号交接

包含账号、作业管理和预算等完整教师职责的独立文档见 [教师端职责清单](../features/teacher/responsibilities.md)。

产品方式已确定：开通账号、发放初始密码、首次登录改密；密码重置需使旧会话失效并再次要求改密。

用户已进一步明确：账号开通、初始密码发放、密码重置及操作入口属于教师端职责。以下作为教师端交付依赖记录，不再列为待用户决定的分工：

| 已定责任 | 需要落到的交付 |
|---|---|
| 负责模块 | 教师端负责人实现开通、发放和重置管理功能 |
| 操作入口 | 教师端提供，具体页面及实现由教师端安排；当前不假定该入口已经存在 |
| 开通／发放／重置如何联调 | 提供合成账号，初始密码只经受控渠道发放，首次改密标记及重置会话处理真实生效 |

该入口应调用共享账户服务，并遵守 RV02 的用户行锁协议，不能只批量写 password_hash。学生侧负责首次改密页面、登录及续期消费，教师端负责开通／发放／重置及管理入口。已同步总设计 C02，后续联调验证教师端交付情况。

C09 的教师总预算是已定职责的接口交接，不是新的分工决策。其他已定调整无需用户重新选择。
