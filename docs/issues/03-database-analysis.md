## AN01 第一优先：互评流程与契约

- [ ] 设计评审批次、答案快照、匹配预览、正式任务、原始评价/维度分和评分修订，新增迁移与完整fixture。
- [ ] 截止前最后一次有效正式提交进入互评，排除草稿/撤回并固定版本。
- [ ] 明确批次任务结构；现analysis_jobs.submission_id必填，不能给整轮匹配填虚假提交ID。
- [ ] 交付匹配预览/发布服务、匿名任务与评分DTO，让T开放入口和S评分界面可接入。
- [ ] 先用确定性基础匹配或受约束mock，真实检查无自评、评审者不重复、人数/负载和不可行情况；输出版本与is_mock。
- [ ] 发布检查输入未变并原子生成任务，之后不随意洗牌；教师可追溯映射，学生DTO不含作者/其他评审者。
- [ ] 原始评分写入由S实现或协作，复用A的数据和校验；保留分项/总分/评语/时长/版本。

交付：迁移、服务/API、成功/无解/越权样例。6份答案各2名评审者的一轮真实联调，T可预览开放，S可完成评分；此时不要求复杂匹配研究完成。

## AN02 第二优先：聚合、四类异常与教师处置

- [ ] 聚合固定量表与原始评价快照，先用可解释基线；输出归一化分、有效样本数、依据及版本。
- [ ] 为单次偏离、长期高/低、异常时长、稳定异常关系提供检测框架；初步模拟证据明确标记，证据不足独立表示。
- [ ] 教师KEEP/DOWNWEIGHT/INVALIDATE_AND_REVIEW/OVERRIDE_SCORE请求包含理由和期望版本；疑似异常不自动扣分。
- [ ] 统一执行处置、权重/有效性、重算、补评与审计；重复请求不重复处罚，多规则不重复降权，失败不残留“已处理”。
- [ ] 缺评/低样本/无评价不补零；补评排除作者/已评者，无解解释原因。

交付：原始评价→聚合/证据→教师决定→实际变更→重算闭环。T/S读取稳定DTO，模拟值落库一次，不随刷新随机变化。

## AN03 第三优先：结算、发布、学习统计

- [ ] 题目成绩、人工修订、总分、发布快照和有效版本；覆盖纯编程、纯主观、混合。
- [ ] MOCK_ACCEPTED没有正式得分，不推导100分；UI需要模拟成绩时单独标识并与正式发布隔离。
- [ ] 按题目满分归一化及权重结算，区分未交/待评/系统失败，未交政策先共同确认。
- [ ] 发布前检查评审结束、样本完整和异常处置，固定题分/总分/依据；改分新增版本和理由，不覆盖旧记录。
- [ ] 个人学习、班级通过率/成绩分布/常见错误/经验难度/知识点掌握；标注分母、样本、范围与缺失。
- [ ] 教师/学生统计权限正确，教师难度与经验难度分开，不从提交快推断AI使用或态度。

交付：T按题/学生/班级查分，S看本人已发布反馈，两端同版本可手算对账。分析统计页面归A，T/S接导航与对应业务入口。

## AN04 接入真实代码评测

- [ ] 选择隔离环境/首版语言，固定编译器、测试版本与判题规则，不在业务后端无约束执行学生源码。
- [ ] 编译、逐例执行、资源限制和清理；AC/WA/TLE/RE及编译失败/系统故障分开。
- [ ] 任务租约、崩溃回收、重测代次与旧结果拒绝，不能沿用开发单worker手工恢复作为正式保障。
- [ ] 返回实际时间/内存，隐藏测试和内部文件不泄露，标识真实实现。

交付：真实源码得到可复现判定与资源记录。环境工作量大时三人明确协助者，不以随机判题替代验收。

## AN05 三人并行研究算法

- [ ] 共同认领匹配/聚合/检测，明确研究负责人、基线、输入规模与指标。
- [ ] 算法包独立于Web/数据库，线上与离线实验调用同一实现。
- [ ] 匹配比较公平性/重复关系/可行率，聚合比较稳定性/误差，检测按四类报告查准/查全/误报/证据不足。
- [ ] 固定seed、数据/参数/实现版本与环境；校准和测试分开，标签不作为检测输入。
- [ ] 各算法交思想、流程/伪代码、正确性或适用条件、时空复杂度、原始结果、图表和失效场景。

复杂能力模型、代码相似性、AI率、自动报告暂列扩展，不阻塞必做流程；学习分析先完成可解释统计。
