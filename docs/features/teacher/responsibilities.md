# 学生作答联调所需的教师端职责

日期：2026-10-24。本文单列本次讨论中已明确归教师端的功能及对接要求，供教师端负责人开发和交接。职责归属已确定，具体页面布局及实现由教师端安排。

**本文是职责与验收清单，不表示功能已经实现。**现有基础按当前仓库核对：题库、测试配置及名单导入已有实现；账号开通／发放／重置、作业管理入口、测试总预算尚待补齐。

当前只覆盖学生读题、作答、提交和评测联调需要的教师能力，互评、评分聚合和正式成绩发布不列入这次交接。

## 1. 职责总表

| 编号 | 教师端负责的内容 | 当前基础／缺口 | 对学生模块的交付 |
|---|---|---|---|
| TD01 | 学生账号开通 | 名单导入已有，创建的是 PENDING、无密码账号；开通入口未实现 | 账号可登录，课程成员和学生资料有效，首次必须改密 |
| TD02 | 初始密码生成及发放 | 未实现 | 教师端提供受控发放流程，可用合成账号完成真实联调 |
| TD03 | 密码重置及管理入口 | 未实现 | 重置后旧会话失效，重新使用初始密码并强制改密 |
| TD04 | 作业创建、选题、应交名单及发布 | 现有作业表和演示数据可读；正式写入入口未实现 | 学生只能读到自己名单内的非草稿作业及绑定题目 |
| TD05 | 修改 DDL、提前关闭和重新开放 | 现有状态／截止校验已支持读取，教师操作入口未实现 | 学生读取同一状态和截止，后端统一限制新提交 |
| TD06 | 编程测试配置、公开性及测试总预算配置／发布校验 | 测试点、公开标记、语言和单点资源配置已有；总预算字段及校验待对接 | 冻结可用测试配置，预算与节点支持能力一致，隐藏内容不外发 |
| TD07 | 教师侧采用版本及提交信息口径对齐 | 已有教师提交列表和详情；当前候选服务待学生／评测模块实现 | 教师展示采用版本时复用共享选择结果，不自行另选 |
| TD08 | 接入统一登录、课程选择及共享变更回归 | 共用前端已有，当前登录／课程状态仍偏向教师入口 | 教师工作台继续可用，接收统一课程上下文 |

## 2. 账号管理：TD01–TD03

### 2.1 账号开通

- 教师端提供账号开通操作入口，不能把名单导入成功直接视为账号已经可登录。
- 复用现有 users、student_profiles、course_members，不另建学生身份或密码表。
- 开通时设置可用账号状态、初始密码哈希和 `must_change_password=true`。该标记及配套迁移属于共享认证增量，需共同对接。
- 首次改密前的账号只能完成改密、会话查询、续期和退出等必要操作；该后端限制由共享认证服务落实。
- 再次导入名单不能自动重置已有密码、重新开通停用账号或重复发放初始密码。

### 2.2 初始密码发放

- 教师端负责初始密码生成、发放流程及操作入口；具体页面由教师端设计。
- 每个账号使用独立生成的初始密码，数据库保存哈希；不把明文放进名单查询、通用响应或日志。
- 发放后的学生走统一登录页，完成强制改密后再选择课程。学生端不增加公开注册或自行开通账号入口。
- 联调先提供合成账号及可控发放结果，不把生产密码写入 Git、示例 JSON 或演示文档。

### 2.3 密码重置

- 教师端提供密码重置入口，生成新的初始密码并重新发放；不查询或恢复原明文密码。
- 重置设置 `must_change_password=true`，使旧登录会话失效；旧会话不能通过自动续期复活。
- 管理操作需验证教师身份及目标学生的授权范围，不接受前端自报角色。实际账号不跨课程混用教师／学生身份，不据此额外设计特殊重置规则。
- 必须调用共享账户服务，遵守登录、改密、重置统一的用户行锁和锁内凭据刷新协议，不能只批量修改 password_hash。
- 登录创建会话与重置交错时，旧密码不能在旧会话删除后创建一份仍可用的新会话。

学生侧负责登录、首次／主动改密及自动续期。会话空闲 2 小时、单次登录绝对上限 24 小时；这些认证规则由共享服务统一执行，教师端管理入口复用该服务。

## 3. 作业发布与应交名单：TD04

- 教师创建草稿，选择题目、设置题目分值／权重、提交截止和应交名单，检查完整性后发布。
- 选择题目时固定 `problem_version_id`；编程题固定 `test_suite_id`，主观题固定 `rubric_id`。各配置必须同课程、归属同一题目版本，且题目版本本身已冻结。
- 不仅检查配置表标记为 FROZEN，还需检查题干和配置完整有效；不发布可编辑草稿或跨版本测试集。
- 应交名单保存到 assignment_participants，并保留发布时班级快照；仅有选课关系不代表自动参加全部作业。
- 名单导入、课程成员、作业应交名单是不同层次。导入新学生不自动改写已发布作业的历史名单。
- 发布事务同时固定版本、配置、名单、发布者和时间，失败整体回滚，不出现半份作业可见。
- 沿用 DRAFT／OPEN／CLOSED：草稿学生不可见，已发布作业只向名单内学生开放，提交仍受服务端时间检查。
- 分值、权重和题型配置遵守现有约束；主观题当前保留量表及评审人数配置，但本轮不会因此自动启动互评。

## 4. DDL 与开关管理：TD05

- 教师端提供修改 DDL、提前关闭、重新开放的操作入口，更新现有 assignments 状态和截止字段，不另建一套学生侧开关。
- 所有日期带时区传输、统一按 UTC 保存；界面可本地化显示。
- 重新开放需确保状态为 OPEN 且新截止在未来；延期与相关日期仍需满足数据库约束，例如已配置评审截止时应晚于提交截止。
- 这些变更不修改历史提交时间、源码、题目／测试版本或已有评测结果。
- 提前关闭或到达 DDL 只限制新正式提交；已成功接收的排队／执行任务继续处理，截止后允许按共享规则重评服务故障的原提交。
- 学生不接受客户端自报时间。当前作业是否可交由后端读取最新状态及截止决定。

不在本次交接中加入自动延期、补交特批或修改历史答案等额外业务。

## 5. 测试配置和总预算：TD06

### 5.1 沿用的教师配置

- 语言范围为 Python 3（python3）、C++（cpp）、C（c）、Java（java），每题 allowed_languages 决定学生可选范围。
- 教师配置测试输入、期望输出、顺序、权重、公开性、CPU／内存限额和输出比较方式。
- 现有 `test_cases.is_public` 及教师“公开测试点”选项继续使用，新测试点默认隐藏。
- 题面 public_examples_md 与公开测试点独立维护，不承诺自动同步。
- 题目冻结／发布后使用固定配置；修订通过新版本或快照处理，不直接改写学生已提交所依赖的配置。
- 发布前与评测提供的语言／配置能力校验对齐，永久不支持的配置应明确报错，不让学生任务永远排队。

### 5.2 测试集总执行预算

**教师端负责总预算的配置及发布校验；评测模块负责提供预算规则、可支持上界和实际执行保护；学生端只展示配置及反馈。**

- 预算规则考虑编译、测试点数量、逐点墙钟上限、环境启动和清理开销，不能把全题简单固定为 60 秒。
- 教师输入／发布的预算需在节点支持范围内，并与测试数量及单点资源配置一致，非法配置明确拒绝。
- 当前教师模型尚无总预算字段；具体字段、不可变配置快照和增量迁移需由教师端、数据库和评测模块对齐。不能把新字段标为已实现。
- 缺少总预算字段的开发演示数据，可由评测受控配置暂时推导，并标明来源；不是学生 API 代替教师编辑正式配置。
- 开发 LOCAL 执行暂不测 CPU／内存，不能伪造这些指标；后续 Linux 仍按教师冻结限额与节点保护执行。

教师端不承担任务调度、个人同时执行上限、重评冷却或故障熔断的内部实现，这些由学生／评测模块交付。

## 6. 教师侧提交采用口径：TD07

- 编程题采用共享服务给出的当前最佳：通过数更多，其次 CPU 时间更少、内存更少，完全相同时取最近版本；四种语言不加权。
- 开发 LOCAL 不测量的资源为空，不能当零；缺失指标按共享比较器处理，不由教师端另写算法。
- 主观题取截止规则内最后一次未撤回有效提交；提交历史继续保留，不能用覆盖答案代替新版本。
- 教师界面展示采用版本时读取共享选择结果，不简单用最近编程提交替代最佳。
- 排队、执行和服务故障尚未解决时显示处理中；不能把未完成任务或 Mock 判定当作正式分数。
- LOCAL 和后续 Linux 记录执行环境，按当前评测上下文读取，避免跨环境混比资源。

本项是教师消费学生／评测模块结果时的对接约定，不要求教师端在本轮另做评分聚合、成绩发布或复杂分析页面。

## 7. 公共模块与数据库协作：TD08

- 全平台统一登录，成功后先选课程，再按课程权限进入工作区；教师端无需另建一套登录协议。
- 登录、首次改密、续期、课程选择由共享／学生侧本轮扩展，教师端配合接入课程上下文并回归已有题库、导入和未保存编辑保护。
- 数据库继续沿用 PostgreSQL、SQLAlchemy 及现有表关系；教师侧所需账号标记、预算字段等通过协调后的增量迁移实现，不改写已应用迁移。
- 新接口先对齐请求／响应、权限、错误和事务规则；完成实现后再更新当前 API、OpenAPI 及运行说明。
- 当前教师职责明确，具体页面／脚本形态由教师端负责人安排；学生模块不因该依赖未交付就自行扩展教师管理功能。

## 8. 教师端交付验收清单

以下为待执行场景，不是现有测试通过记录。

- [ ] 导入合成学生后仍为待开通；教师开通、发放初始密码后可登录，首次必须改密。
- [ ] 重置后旧密码／旧会话不可继续使用，新初始密码触发强制改密；与登录并发仍成立。
- [ ] 重复导入不自动改密码或重置账号；无权教师不能管理目标账号。
- [ ] 草稿学生不可见，发布后仅应交名单内学生可读可交。
- [ ] 发布固定题目和测试／量表版本，非法配置整体回滚；发布后改题库不影响旧作业。
- [ ] 延期、关闭和重开后，学生端状态与服务端接收规则一致；已接收任务继续评测。
- [ ] 总预算有明确来源、合法性和节点支持校验，越界配置不会形成永久排队任务。
- [ ] 公开／隐藏配置正确；学生响应不含教师参考和隐藏输入输出。
- [ ] 教师侧需要展示采用版本时，与学生侧共享选择结果一致，不混比 LOCAL／Linux 资源。
- [ ] 共享登录和选课调整后，教师题库、名单导入及未保存变更保护保持可用。
